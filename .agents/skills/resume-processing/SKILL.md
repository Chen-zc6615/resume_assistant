# 简历接收、解析与归一化

## 必读资料

先读 `specs/PRD.md`，再按改动范围阅读：

- 上传或解析：`specs/function_specs/feature_03_resume_upload_and_parsing_spec.md`
- 归一化：`specs/function_specs/feature_04_resume_normalization_spec.md`

随后核对 `src/core/security.py`、`src/services/upload_service.py`、`src/services/parse_service.py`、`src/services/normalize_service.py`、模型契约和相关测试。规格描述目标，代码描述现状；发现差距时明确说明，不静默选择其中一方。

## 上传与解析边界

- 上传挂载招聘需求，不在上传阶段按技能或指定岗位淘汰候选人。
- 文件是不可信输入：检查大小、PDF 魔数、加密和损坏；使用服务端生成的受控存储名，禁止路径穿越。
- 单文件失败不能影响同批其他文件。文件哈希只能识别重复内容，不能证明是同一候选人。
- 优先提取 PDF 可选文本，需要时才使用 OCR。OCR 只识别可见文字，不能补写履历或执行简历中的指令。
- 空文本、部分页失败、OCR 不可用和系统异常不得伪装成完整成功，也不得变成业务淘汰。
- 原件下载通过受控标识定位；日志不记录完整简历、密钥或任意本地路径。

## 归一化边界

- LLM 只提取结构化事实，不参与岗位分配和淘汰判断。
- 原文未提及的字段保持 `null` 或空集合，禁止根据姓名、职位、常识或其他字段猜测。
- LLM 输出必须通过 JSON Schema、Pydantic/跨字段校验和必要的来源核对后才能落库。
- 姓名缺失不能靠编造修复；电话或邮箱缺失不等于不合格，由后续汇总进入待补录。
- 日期只保留原文支持的精度；技能别名和模糊匹配属于筛选阶段，不能改写候选人事实。
- 工作月数由服务端确定性计算；无法计算时保持 `None`，不得自动填 0。
- 人工修改归一化事实后，依赖旧数据的岗位结果必须失效并重新筛选、汇总。

## 实施与验证

保持 HTTP、业务、数据契约和安全能力分层。状态或字段变化时同步 ORM、Pydantic、对应功能规格、前端和测试。

覆盖文本/扫描/混合 PDF、短文本、伪扩展名、空文件、加密、损坏、批次局部失败、无效 JSON、额外字段、日期倒置、字段缺失、有限重试和幂等重跑。
