# 登录与身份认证

## 必读资料

依次阅读：

1. `specs/PRD.md` 的用户认证状态机和登录边界。
2. `specs/function_specs/feature_01_login_spec.md`。
3. 与本次改动直接相关的模型、服务、API、前端路由和测试。

登录规格是目标设计；当前代码尚未完整实现认证。先确认现状，不得把文档中的目标能力描述为已经上线。

## 不可破坏的安全边界

- 本期只做内部账号登录、恢复会话、退出、失败锁定和账号禁用；不要自行加入注册、找回密码、第三方登录或细粒度角色权限。
- 使用成熟的自适应密码哈希。禁止保存或记录明文密码、密码哈希、原始会话令牌和完整 Cookie。
- 会话令牌必须由密码学安全随机源生成，数据库只保存令牌哈希。
- 会话 Cookie 至少设置 `HttpOnly`、`SameSite=Lax`、`Path=/`；生产 HTTPS 环境启用 `Secure`。
- Cookie 认证的写操作必须有 CSRF 防护；带凭据 CORS 不得允许任意来源。
- 用户名不存在与密码错误使用统一反馈。连续失败计数和“第 5 次失败锁定 15 分钟”必须原子更新。
- 每次受保护访问都校验会话未过期、未撤销且账号正常。未认证返回 401，无权限返回 403。

## 分层与迁移

- `src/api/` 只处理 HTTP 输入输出，通过统一依赖取得当前用户。
- `src/services/` 负责登录、锁定、会话创建与撤销的业务事务。
- `src/core/` 放密码哈希、令牌与 Cookie 安全能力；`src/db/` 提供数据库会话。
- 登录接入后，`hr_id`、`created_by`、`reviewer_id` 等操作者必须来自可信会话；客户端伪造字段不能改变真实身份。
- 前端启动时调用 `/api/auth/me` 恢复状态；401 清理状态并跳转登录页，403 不应退出有效会话。

## 验证

至少覆盖：成功登录、统一错误、防账号枚举、并发失败锁定、锁定到期、退出幂等、会话过期/撤销、账号禁用、Cookie 属性、CSRF 和身份字段伪造。

会话时长、是否设置空闲超时和初始账号创建方式仍需在实现前确认，不要擅自硬编码。
