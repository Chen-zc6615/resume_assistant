# 功能八 简历审核与入人才库

版本：v1.0 草案｜日期：2026-10-09。

## 1. 目标与原则

HR 对原始简历、归一化事实、各岗位筛选结果和多岗位汇总结果进行人工核对，明确确认是否完成本次筛选。审核通过不会自动沉淀候选人才库；长期储备是审核后的独立可选操作。

沿用现有人工编辑、确认通过、人工筛除和候选人才库能力。可信审核身份、版本核对、岗位结果关联与完整审计记录为新增目标设计。

## 2. 审核内容与操作

审核页并列展示原 PDF/解析文本、结构化草稿和字段证据，展示岗位条件快照、逐项结果和多岗位汇总。HR 可以：

- 修正原文提取错误或补充原文已有信息，保留修改前后值、原文依据和操作者。
- 对解析或归一化失败记录人工补录结构化草稿，仍须通过同一字段校验。
- 对信息不足和未达标记录核对后重新执行相应阶段，不得直接改写筛选结果绕过规则。
- 对已通过且结果有效的记录确认完成本次筛选，或对整份简历执行人工筛除并填写原因。
- 对需要长期复用的候选人单独执行“沉淀人才库”，记录来源需求、来源岗位和备注。

禁止凭经验补造事实。外部补充候选资料的来源与确认方式尚未定义，本版本只接受原简历依据。人工例外放行、跨岗位人才储备和筛选不通过直接入库尚未定义，本版本不开放。

## 3. 审核确认前置条件

1. 草稿通过 ResumeProfile 与跨字段校验，姓名非空。
2. 至少一个当前有效岗位的最新筛选结果为 PASS，多岗位汇总状态为待审核入库，电话和邮箱已经补全。
3. 该次审核明确关联具体通过岗位；其他岗位不通过结果保留，不因审核确认改为通过。
4. HR 已阅读当前版本并点击确认，提交可信 reviewer_id、reviewed_at、确认版本及关联结果标识。
5. 确认前重新校验输入与工作月数；若重算导致已审核事实或筛选结论变化，返回版本冲突并要求重筛、重新确认，不能静默写入新值。

同一简历对应多个岗位时只完成一次简历审核，岗位关系及各自结论独立保留。至少一个岗位通过是确认完成本次筛选的门槛；其他岗位的不通过结果不会因此改为通过。

## 4. 数据与事务

ReviewRecord：review_id、resume_id、normalization_version、job_screen_result_ids、reviewer_id、decision（confirmed/discarded/returned）、reason、changes、reviewed_at。

TalentPoolEntry：pool_id、resume_id、source_requirement_id、source_job_id、note、created_by、created_at；同一简历最多存在一条有效沉淀记录，不复制归一化简历事实。知识库派生数据另记录 knowledge_sync_status（pending / syncing / success / failed）、knowledge_document_id、knowledge_chunk_count、knowledge_sync_error 和 knowledge_synced_at，不在人才库表中保存 Wiki 正文。

确认通过的事务写入审核记录并将简历处理状态置为已完成，同时记录通过岗位；失败时全部回滚并保持可重试。沉淀人才库使用独立事务，只创建人才库关联，不改变简历处理状态和岗位筛选结论。

人才库以 resume_id 唯一约束防止同一简历重复沉淀；不同文件属于同一候选人的情况只提示可能重复，不按姓名、电话自动合并。重复提交确认或沉淀请求应返回已有结果，不创建重复记录。

人才沉淀提交成功后再同步脱敏归一化数据到知识库；知识库故障不得回滚人才沉淀事务。同步失败记录为 failed 并允许人工重试，同一 knowledge_document_id 使用幂等覆盖。知识库只接收检索所需事实，不接收电话、邮箱、PDF 原文/路径或 HR 内部备注。

## 5. 状态、接口与界面

待审核入库 → HR 确认通过 → 已完成。HR 人工筛除会将整份简历置为初筛不通过，并以“人工筛除”前缀记录必填原因；该操作不是仅移除某一个岗位。资料被修改时应重新筛选和汇总后再确认。

沿用现有简历资料编辑接口保存人工修正；目标增加 expected_normalization_version 和修改依据，并使相关岗位结果失效，重新执行岗位筛选与汇总。确认通过使用 `POST /api/resumes/{resume_id}/confirm`，人工筛除使用 `POST /api/resumes/{resume_id}/reject`；人才库沉淀使用独立的 `POST /api/talent/pool`，并记录来源与备注。

不存在返回 404，状态或版本冲突返回 409，字段错误返回 422。重试仅针对暂时性存储错误，采用有限退避，最多三次；校验、权限和版本冲突不自动重试。客户端超时后先查询入库结果，再重发幂等请求。

处理列表保留已完成、待审和筛除记录；候选人才库只展示明确执行过沉淀操作的记录。日志及审计记录按业务权限读取，身份来自可信会话而非客户端任意填写。鉴权接入方式沿用项目机制，缺失时作为上线前实现项。

## 6. 验收标准

- 未经 HR 明确确认，简历不能从待审核直接变为已完成。
- 人工编辑后旧结果失效，未经重筛和再次确认不能标记为已完成。
- 解析失败记录可人工恢复，但须经过完整后续流程。
- 多岗位一通过一不通过时只完成一次简历审核，两个岗位结果均保留。
- 人工筛除作用于整份简历，原因必填并与规则淘汰区分。
- 审核通过不会自动沉淀人才库；明确点击沉淀后才创建人才库记录。
- 重复确认或重复沉淀不创建重复记录。
- 过期审核版本被拦截，人工筛除原因和全部修改轨迹可追溯。
