# 功能五 岗位分配

版本：v1.1 草案｜日期：2026-10-14｜实现状态：与当前全量分配逻辑对齐。

## 1. 目标与边界

将完成归一化的简历分配到所属招聘需求下的全部开放岗位，为逐岗位硬性条件初筛建立输入。一份简历可以同时进入多个岗位组。

招聘需求是岗位集合容器，自身不设置最低学历、工作年限或必备技能等筛选条件。分配阶段也不根据技能、JD 相似度或模型评分提前淘汰简历；是否满足岗位要求由功能六的确定性规则判断。

## 2. 前置条件与分配范围

自动分配必须同时满足：

- 招聘需求真实存在，简历已经加入该需求池。
- 简历具有通过校验的归一化数据。
- 岗位属于该招聘需求且状态为开放。

系统遍历需求下全部开放岗位，为每个“简历—岗位”组合建立岗位组关联。草稿和关闭岗位不参与自动分配。需求下没有开放岗位时不创建关联，简历保留待初筛状态并提示“需求下没有开放岗位，待人工分岗”。

## 3. 分配记录

岗位分配使用 `JobResumeGroup` 保存：

| 字段 | 含义 |
| --- | --- |
| job_id、resume_id | 岗位与简历标识；同一组合唯一 |
| added_by | `auto:assignment` 表示系统分配，HR 标识表示人工调整 |
| match_detail | 必备技能和加分技能的命中明细，仅用于说明，不作为分配门槛 |
| created_at | 关联创建时间 |

重复执行分配时，已存在的组合直接跳过，不创建重复记录。技能命中明细不得被解释成通过结论或匹配分数。

## 4. 流程与人工调整

1. 简历归一化成功后进入待初筛。
2. 系统取得所属需求下的全部开放岗位。
3. 系统幂等创建全部“简历—岗位”关联。
4. 每个岗位组分别进入功能六执行硬性条件初筛。
5. HR 可以手动增加或移除岗位组关联，并对调整后的有效岗位重新筛选。

自动分配是默认主流程，人工操作只用于调整分配结果。移出某岗位不删除该岗位的历史筛选记录，但该历史结果不再参与当前多岗位汇总。

## 5. 接口与界面

上传批次完成归一化后自动调用分配服务。需求池重分配使用 `POST /api/requirements/{requirement_id}/reassign`；岗位组支持查看、手动加入和移出简历。

界面展示所属需求、开放岗位、分配来源和技能命中明细。命中明细必须标注为参考信息，不显示未经定义的匹配分数，也不得暗示简历已经通过岗位筛选。

## 6. 验收标准

- 每份符合前置条件的简历进入需求下全部开放岗位。
- 草稿岗位、关闭岗位和其他需求的岗位不参与分配。
- 必备技能未命中仍然进入岗位组，由功能六给出筛选结论。
- 重复执行不会产生重复关联。
- HR 调整一个岗位关联不影响其他岗位关联。
- 没有开放岗位时不误报处理成功，并给出待人工分岗提示。
