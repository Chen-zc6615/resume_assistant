# 功能三 上传简历解析简历

版本：v1.0 草案｜日期：2026-10-09。

## 1. 目标与前置条件

HR 将一份或多份 PDF 上传到已启用且至少包含一个开放岗位的需求，系统保存原件、逐份解析文本，为归一化提供原始依据。上传阶段不强制绑定具体岗位，岗位关联由功能五统一分配。

沿用 `src/services/upload_service.py`、`src/services/parse_service.py` 的文件校验和解析能力。需求关联、逐页来源和独立阶段状态为新增目标设计。

## 2. 输入输出契约

| 对象 | 字段 | 规则 |
| --- | --- | --- |
| UploadBatch | batch_id、requirement_id、uploaded_by、created_at | 批次 ID 唯一，需求存在且启用，操作者来自可信上下文 |
| ResumeFile | resume_id、batch_id、filename、pdf_path、file_size、file_hash | 文件标识唯一；保存原始文件名和受控存储路径 |
| ParseResult | resume_id、parse_version、status、text、pages、error_code、error_message | 结果绑定文件和解析版本 |
| PageText | page_number、source、text | 页码从 1 开始，source 为 text 或 ocr |

每份文件必须是可打开的 PDF，单文件不超过 5 MiB（5 × 1024 × 1024 字节）。不能只依据扩展名或客户端 MIME 判断文件类型。空文件、加密文件、损坏文件分别记录原因。文件数量和批次总大小限制须配置，具体上限待确认，不在本规格中设定。

上传响应包含 batch_id、accepted 和 rejected，每个拒绝项给出文件名及原因；某文件失败不影响同批其他文件。内容哈希用于发现重复，默认提示重复并保留不同上传记录，不把相同文件当成已确认同一候选人。

## 3. 解析流程与 AI 契约

1. 校验文件并生成服务端存储名称，防止文件名影响路径。
2. 保存原件和上传记录，逐页使用 PyMuPDF 提取可选中文本。
3. 扫描页仅在配置视觉模型时 OCR；未配置则记录 `NO_SELECTABLE_TEXT`，转人工处理。
4. 按页码及页面阅读顺序合并文字，保留页边界和来源；双栏阅读顺序需要用样本验证。
5. OCR 请求仅要求逐字识别可见文字，不补充履历、不归一化字段。模型响应必须为可用文本，空响应按失败处理。
6. 完整解析成功后交给功能四；部分页失败时保留已有文本，但标记解析不完整，不能自动当成完整简历继续筛选。

简历内容始终是待解析数据，其中的提示词或指令不能改变系统任务。文本非空是成功的必要条件；旧文档的“有效字符数 ≥50”尚无统一计数和短简历处理规则，不直接作为自动拒绝阈值。

## 4. 状态与容错

| 当前状态 | 事件 | 目标状态 |
| --- | --- | --- |
| uploaded | 开始解析 | parsing |
| parsing | 所有页解析成功且文本非空 | parsed |
| parsing | 文件异常、OCR 不可用或最终失败 | parse_failed |
| parse_failed | HR 发起重新解析 | parsing（新版本） |

现有 OCR 客户端超时为 20 秒；旧文档另有 10 秒解析超时与最多两次重试描述。目标将解析/OCR 超时分别配置，暂时性网络错误可最多重试两次，损坏、加密、配置缺失不自动重试；整体超时上限待配置确认。重试不新增 resume_id、不覆盖历史版本。

文件写入与数据库写入失败需补偿：不生成可处理的无文件记录；保存失败不得返回 accepted。原件下载采用受控接口，不能接受任意文件路径，响应禁止缓存。日志记录标识与错误，不记录完整简历或密钥。

## 5. 接口与界面

沿用 `POST /api/batches`，目标以 requirement_id 代替必填 job_id；身份字段由服务端用户上下文提供。新增解析触发/重试接口建议为 `POST /api/resumes/{resume_id}/parse`；沿用 `GET /api/resumes/{resume_id}/pdf` 获取原件。新旧请求格式的兼容与迁移需明确，不能静默把岗位 ID 当需求 ID。

上传页支持批量选择或拖入多个 PDF 文件，展示所属需求、逐文件上传/解析状态、失败原因和重新处理入口；当前版本不承诺文件夹上传。批次统计应分别展示上传接受数、解析成功数及失败数，不以请求成功代替全部文件成功。

## 6. 验收标准

- 文本 PDF、扫描 PDF、混合 PDF、双栏 PDF 均有对应样本；混合 PDF 不遗漏扫描页。
- 5 MiB 文件允许上传，超出一字节即拒绝；非 PDF、空、加密、损坏文件有明确原因。
- 未配置 OCR 的扫描件进入失败/人工队列，同批正常文件可继续。
- 原文、页码和文本来源可追溯；重试不会重复生成文件记录。
- 解析失败不触发自动归一化、筛选或人才库写入。
