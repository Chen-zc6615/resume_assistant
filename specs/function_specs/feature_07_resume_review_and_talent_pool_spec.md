# 功能七 简历审核与入人才库

版本：v1.0 草案｜日期：2026-10-09。

## 1. 目标与原则

HR 对原始简历、归一化事实、需求初筛和岗位筛选结果进行人工核对，明确确认后将结构化简历写入人才库。自动处理成功和初筛通过都不是入库授权。处理草稿与正式人才库记录分开管理。

沿用现有人工编辑、commit、discard 接口和正式简历主表/子表结构。可信审核身份、版本核对、两阶段结果关联与完整审计记录为新增目标设计。

## 2. 审核内容与操作

审核页并列展示原 PDF/解析文本、结构化草稿和字段证据，展示需求与岗位条件快照、逐项结果及版本。HR 可以：

- 修正原文提取错误或补充原文已有信息，保留修改前后值、原文依据和操作者。
- 对解析或归一化失败记录人工补录结构化草稿，仍须通过同一字段校验。
- 对信息不足和未达标记录核对后重新执行相应阶段，不通过直接改写筛选结果绕过规则。
- 对已通过且结果有效的记录确认入库，或记录人工筛除原因。

禁止凭经验补造事实。外部补充候选资料的来源与确认方式尚未定义，本版本只接受原简历依据。人工例外放行、跨岗位人才储备和筛选不通过直接入库尚未定义，本版本不开放。

## 3. 入库前置条件

1. 草稿通过 ResumeProfile 与跨字段校验，姓名非空。
2. 需求初筛 passed 且有效，至少一个 active 岗位分配的最新岗位筛选 passed。
3. 该次审核明确关联具体通过岗位；其他岗位不通过结果保留，不因人才入库改为通过。
4. HR 已阅读当前版本并点击确认，提交可信 reviewer_id、reviewed_at、确认版本及关联结果标识。
5. 入库前重新校验输入与工作月数；若重算导致已审核事实或筛选结论变化，返回版本冲突并要求重筛、重新确认，不能静默写入新值。

同一简历对应多个岗位时人才库只保存一份候选档案，岗位关系及各自结论独立保存。至少一个岗位通过作为本草案默认入库门槛；“全部岗位必须通过”或“允许无岗位储备入库”须另行确认后修改。

## 4. 数据与事务

ReviewRecord：review_id、resume_id、normalization_version、requirement_screen_result_id、job_screen_result_id、reviewer_id、decision（confirmed/discarded/returned）、reason、changes、reviewed_at。

TalentEntry：talent_id、profile_id、resume_id、review_id、status、created_at；可通过现有 resume_profiles 与新增人才库元数据关联实现，不必复制一套简历事实表。

单次入库事务写入审核确认、resume_profiles、profile_skills、education_experiences、work_experiences、project_experiences、人才库关联与处理状态。所有子记录关联同一数据库生成 profile_id。任一步失败全部回滚，原草稿及历史仍可读。

resume_id 唯一约束防止同一文件记录重复入库；不同文件同一候选人只提示可能重复，不按姓名、电话自动合并。候选人合并和已入库档案修改流程待定义。重复提交同一已成功确认请求返回原 profile_id，不能重复插入子记录。

## 5. 状态、接口与界面

待审核 → 审核中 → confirmed → committed；审核中可 returned（修改后重筛）或 discarded（人工筛除）。事务失败保持可重试的待入库状态，错误不作为业务拒绝。确认状态与 committed 在事务中一致提交，不能出现“确认已保存但档案部分写入”。

沿用 `PUT /api/resumes/{resume_id}/profile` 保存人工草稿；目标增加 expected_normalization_version 和修改依据，并使所有依赖结果失效，重新从需求初筛执行。沿用 `POST /api/resumes/{resume_id}/commit`，目标请求增加确认版本、审核依据及幂等标识；沿用 discard 接口并增加原因与审核记录。

不存在返回 404，状态或版本冲突返回 409，字段错误返回 422。重试仅针对暂时性存储错误，采用有限退避，最多三次；校验、权限和版本冲突不自动重试。客户端超时后先查询入库结果，再重发幂等请求。

人才库列表仅展示 committed 的正式档案；处理列表保留失败、待审和筛除记录。日志及审计记录按业务权限读取，身份来自可信会话而非客户端任意填写。鉴权接入方式沿用项目机制，缺失时作为上线前实现项。

## 6. 验收标准

- 未经 HR 明确确认，不产生正式档案；页面自动加载、筛选完成不触发入库。
- 人工编辑后旧结果失效，未经重筛和再次确认不能入库。
- 解析失败记录可人工恢复，但须经过完整后续流程。
- 多岗位一通过一不通过时只产生一份档案，两个岗位结果均保留。
- 主表或任一子表写入失败时全部回滚；重复确认不重复写入。
- 过期审核版本被拦截，人工筛除原因和全部修改轨迹可追溯。
