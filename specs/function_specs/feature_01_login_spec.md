# 功能一 用户登录

版本：v1.1 草案｜日期：2026-10-14｜实现状态：新增目标设计，当前代码尚未实现认证。

## 1. 目标与范围

为内部 HR 用户提供账号密码登录和服务端会话认证，确保工作台、业务页面及业务 API 只能由已认证且账号状态正常的用户访问。所有业务操作人的身份必须来自当前可信会话，不能由前端自行指定。

本期范围包括：登录、恢复会话、主动退出、会话过期、连续失败锁定和账号禁用后的访问拦截。不提供公开注册、找回密码、“记住我”、第三方登录和细粒度角色权限管理。

当前代码中的 `hr_id`、`created_by`、`job_created_by` 等客户端身份字段以及默认用户 `hr_admin` 属于迁移前行为。登录功能落地后，受保护接口必须忽略或移除这些可伪造字段，统一使用当前登录用户。

## 2. 账号与会话数据

### 2.1 用户账号

`UserAccount` 至少包含：

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| user_id | 正整数或 UUID，主键 | 用户唯一标识 |
| username | 非空、唯一 | 登录名；保存前执行统一的去空白和大小写规范化 |
| display_name | 非空字符串 | 页面展示名称 |
| password_hash | 非空字符串 | 密码的安全单向哈希，不保存明文 |
| status | normal / disabled | 正常或管理员禁用 |
| failed_login_count | 非负整数 | 当前连续登录失败次数 |
| locked_until | 时间戳 / null | 晚于当前时间时视为暂时锁定 |
| last_login_at | 时间戳 / null | 最近一次成功登录时间 |
| created_at / updated_at | 时间戳 | 服务端生成和维护 |

“暂时锁定”由 `locked_until` 推导，不与账号的 normal / disabled 字段混为同一个状态。连续失败达到 5 次后锁定 15 分钟；锁定期满后允许重新尝试。登录成功后将失败次数归零、清空锁定时间并更新最后登录时间。

### 2.2 登录会话

`AuthSession` 至少包含：

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| session_id | 唯一标识 | 会话记录主键 |
| user_id | 外键 | 所属用户 |
| token_hash | 非空、唯一 | Cookie 中随机令牌的哈希，数据库不保存原始令牌 |
| expires_at | 时间戳 | 会话绝对过期时间 |
| revoked_at | 时间戳 / null | 主动退出或服务端撤销时间 |
| created_at / last_seen_at | 时间戳 | 创建时间与最近使用时间 |

会话有效期必须由配置项控制；具体时长在实现前确认，不得永久有效。首期允许同一账号存在多个有效会话，主动退出只撤销当前会话；账号被禁用时撤销该账号的全部有效会话。

项目不提供公开注册，因此首个管理员或 HR 账号必须通过受控初始化命令或部署流程创建。仓库、镜像、日志和示例配置中不得保存真实密码。

## 3. 登录与锁定规则

1. 用户提交用户名和密码，服务端按统一规范查找账号并校验密码哈希。
2. 用户名不存在或密码错误时，统一返回“用户名或密码错误”，不得说明用户名是否存在。
3. 对存在且未禁用的账号，凭据失败后原子增加连续失败次数，避免并发请求绕过计数。
4. 第 5 次连续失败时设置 `locked_until = 当前时间 + 15 分钟`，锁定期间统一提示“登录失败，请稍后重试”。
5. 锁定期间不创建会话，也不继续延长锁定时间；锁定期满后的下一次尝试重新开始计数。
6. 凭据正确且账号正常、未锁定时创建新会话，重置失败次数并记录最后登录时间。
7. 禁用账号不得创建新会话；已有会话必须失效。对外反馈不得暴露账号被禁用这一内部状态。

登录失败计数与锁定更新必须在事务中完成。密码哈希校验应尽量保持用户名存在和不存在时的处理耗时接近，降低账号枚举风险。

## 4. 会话与 Cookie 安全

- 使用密码学安全的随机会话令牌；数据库只保存令牌哈希。
- 会话 Cookie 使用 `HttpOnly`、`SameSite=Lax`、明确的 `Path=/` 和过期时间；生产 HTTPS 环境必须启用 `Secure`。
- 前端不得把密码或会话令牌保存到 localStorage、sessionStorage、URL 或可读 Cookie。
- 登录、退出和 `/me` 响应设置 `Cache-Control: no-store`。
- 使用 Cookie 认证的写操作必须具有 CSRF 防护；跨域配置不得对任意来源开放凭据请求。
- 每次访问受保护接口时，同时校验会话未过期、未撤销且账号仍为 normal。
- 未认证返回 401；已认证但无权执行的操作返回 403。两者不得混用。
- 日志不得记录密码、原始会话令牌、完整 Cookie 或密码哈希。

密码必须使用成熟的自适应单向哈希算法及库实现，参数由安全配置集中管理；禁止自行设计加密算法或使用可逆加密保存密码。

## 5. 状态转移

账号状态和会话状态分别管理：

| 初始状态 | 事件与条件 | 目标状态 | 系统处理与反馈 |
| --- | --- | --- | --- |
| 未登录 | 访问系统，不存在有效会话 | 未登录 | 展示登录页，拒绝进入业务页面 |
| 未登录 | 凭据正确，账号 normal 且未锁定 | 已登录 | 创建会话，重置失败次数，进入工作台 |
| 未登录 | 用户名或密码错误，失败次数小于 5 | 未登录 | 原子记录失败，统一提示“用户名或密码错误” |
| 未登录 | 连续失败达到 5 次 | 未登录 | 锁定账号 15 分钟，提示“登录失败，请稍后重试” |
| 未登录 | 账号处于锁定期 | 未登录 | 不校验为成功、不创建会话，提示稍后重试 |
| 已登录 | 访问业务页面或 API，会话和账号有效 | 已登录 | 允许访问，并向业务层注入当前用户 |
| 已登录 | 用户主动退出 | 未登录 | 撤销当前会话，清除 Cookie，返回登录页 |
| 已登录 | 会话过期、令牌无效或会话被撤销 | 未登录 | 返回 401，清除 Cookie，提示重新登录 |
| 已登录 | 账号被管理员禁用 | 未登录 | 撤销该账号全部会话，拒绝后续访问 |

## 6. API 契约

### 6.1 登录

`POST /api/auth/login`

请求：

```json
{
  "username": "hr_user",
  "password": "用户输入的密码"
}
```

成功返回 200，设置会话 Cookie，并只返回必要用户信息：

```json
{
  "user_id": 1,
  "username": "hr_user",
  "display_name": "招聘专员"
}
```

凭据错误返回 401；暂时锁定返回 429；请求字段缺失或格式错误返回 422。错误响应使用稳定的错误码和可读提示，不返回账号状态、密码哈希或失败次数。

### 6.2 当前用户

`GET /api/auth/me`

有效会话返回 200 和当前用户必要信息；无效、过期或撤销的会话返回 401。前端以该接口结果恢复登录状态，不以浏览器本地保存的用户对象作为认证依据。

### 6.3 退出

`POST /api/auth/logout`

撤销当前会话并清除 Cookie。重复退出保持幂等，不因为会话已经失效而暴露额外信息；成功返回 204。

## 7. 后端接入要求

- 在 `src/core/` 实现密码和会话安全能力，在 `src/db/` 使用统一数据库会话，在 `src/services/` 实现认证业务，在 `src/api/` 只处理 HTTP 输入输出。
- 提供统一的 `get_current_user` 依赖保护业务路由，不允许各接口自行解析 Cookie。
- API 层将当前用户交给 service；service 只接收可信用户对象或 user_id，不接收前端提交的操作人身份。
- 登录接入后，需求、岗位、上传、筛选、审核、面试和人才库接口均须迁移 `created_by`、`hr_id` 等字段来源。
- 数据库结构改动先更新 ORM，再同步本规格及相关架构说明；认证迁移必须覆盖现有接口测试。

## 8. 前端交互

- 未登录访问任意业务路由时跳转登录页；登录成功后进入工作台或原目标页面。
- 登录表单包含用户名、密码和提交按钮；提交期间防止重复点击。
- 用户名或密码错误显示统一提示；锁定状态显示“登录失败，请稍后重试”，不展示账号是否存在。
- 页面初始化调用 `/api/auth/me`，校验期间显示加载状态，避免先展示受保护页面再跳转。
- 任意业务请求收到 401 时清理前端登录状态并跳转登录页；403 显示无权限，不退出有效会话。
- 顶部用户菜单展示当前用户名称和退出入口；退出成功或本地网络异常后的最终状态都不得继续展示业务数据。

## 9. 审计与隐私

安全日志记录成功登录、失败登录、触发锁定、退出、会话撤销和账号禁用事件，包括服务端时间、用户标识（存在时）、结果和必要的请求来源信息。日志不得记录密码、密码哈希、原始令牌、完整 Cookie 或完整请求体。

业务审计中的操作者统一使用当前登录用户的 `user_id`，展示时再关联 `display_name`。用户名或展示名修改不得改写历史操作归属。

## 10. 验收标准

- 正确凭据可以登录并访问受保护页面和 API；未登录访问被拒绝。
- 用户名不存在与密码错误使用相同提示，不泄露账号是否存在。
- 连续失败第 5 次触发 15 分钟锁定；并发失败也不能绕过计数。
- 锁定期间无法登录，锁定期满后可以重新尝试；成功登录重置失败次数。
- 主动退出后原会话令牌不可继续使用；重复退出保持幂等。
- 会话过期、撤销或账号禁用后，页面与 API 均拒绝继续访问。
- Cookie 和响应符合安全属性要求，前端存储中不存在密码或会话令牌。
- 伪造 `hr_id`、`created_by`、`reviewer_id` 等客户端字段不能改变真实操作人。
- 日志、接口响应和数据库均不出现明文密码或原始会话令牌。
- 登录、锁定、退出、会话过期、禁用账号和身份伪造场景均有自动化测试。

## 11. 实现前待确认

- 会话绝对有效时长，以及是否需要空闲超时。
- 初始 HR 账号的受控创建方式和密码交付流程。
- 是否需要管理员界面管理账号；本期默认仅要求后端具备禁用能力。

以上参数确认后写入配置和部署文档，不得硬编码在前端。
