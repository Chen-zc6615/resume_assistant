# 功能七 多岗位筛选结果汇总

版本：v1.1 草案｜日期：2026-10-14｜实现状态：与当前多岗位归并逻辑对齐。

## 1. 目标与边界

汇总同一简历在当前招聘需求下各有效岗位的最新初筛结果，确定简历进入待审核入库、待人工复核还是初筛不通过。

本功能不是一轮独立的“需求条件初筛”。招聘需求自身不保存最低学历、工作年限或必备技能等筛选条件；所有业务判断来自功能六产生的逐岗位结果。

## 2. 汇总范围

仅汇总简历当前仍然存在岗位组关联的岗位结果，每个岗位只取最新一次筛选结果：

- HR 已将简历移出的岗位不再参与当前汇总，历史结果仍保留。
- 尚未执行筛选或执行失败的岗位不能伪装成通过。
- 已完成入库的简历属于终态，后续重筛不得覆盖其处理状态。

## 3. 汇总规则

结果优先级为：

```text
PASS > PENDING_REVIEW > REJECT
```

| 岗位结果组合 | 简历处理结果 |
| --- | --- |
| 任一岗位 PASS，且电话、邮箱完整 | 待审核入库 |
| 任一岗位 PASS，但电话或邮箱缺失 | 待补录；补全后自动转为待审核入库 |
| 无 PASS，但至少一个岗位 PENDING_REVIEW | 待人工复核 |
| 当前全部岗位均为 REJECT | 初筛不通过 |

一个岗位不通过不得覆盖另一个岗位的通过结果。汇总说明列出每个岗位的最新结果；不通过岗位同时展示首个明确不满足原因，便于 HR 核对。

## 4. 状态与重新汇总

逐岗位筛选完成后自动重新汇总。HR 调整岗位关联、修改归一化事实或重新执行岗位筛选后，必须基于当前有效岗位的最新结果再次汇总。

初筛不通过的简历可以由 HR 恢复为待初筛，在规则或岗位关联修正后重新执行。人工筛除与规则淘汰可以共用“初筛不通过”处理状态，但必须通过原因和审计记录明确区分。

需求下没有开放岗位或没有任何有效岗位结果时，不得判为通过或不通过；简历保持待初筛并提示待人工分岗或等待筛选。

## 5. 接口与界面

汇总由岗位筛选服务内部触发，不要求前端提交汇总结论。需求池重分配和岗位重筛完成后也应触发重新汇总。

界面按简历展示整体处理状态，并能展开查看各岗位的独立结果和原因。整体状态只是导航与工作队列入口，不能替代逐岗位结果记录。

## 6. 验收标准

- 多岗位一项通过、一项不通过且联系方式完整时，整体进入待审核入库。
- 存在通过岗位但电话或邮箱缺失时，整体进入待补录。
- 没有通过但存在待复核时，整体进入待人工复核。
- 只有全部当前岗位明确不通过时，整体才进入初筛不通过。
- 移出岗位后，该岗位历史结果不再影响当前汇总。
- 岗位重筛后使用最新结果，旧结果继续保留用于审计。
- 没有有效岗位结果时不产生虚假的通过或淘汰结论。
