# EVAL — 验收评测协议

> 来源：《5 项目交付验收协议》+《测试样本表》。黄金样本集位于 `evals/golden_datasets/resumes/`（S01-S10 + 3 份优秀简历）。

## 基准岗位 JD

Java 后端开发工程师。硬性：本科及以上；3 年+ Java 后端；掌握 Java、Spring Boot、MySQL。加分：Redis、消息队列、Docker/K8s、微服务、高并发。

## 黄金样本与预期

| 编号 | 场景 | 预期结果 |
|---|---|---|
| S01 完美匹配 | 主链路黄金正样本 | 上传成功；全字段解析；硬性条件全满足→通过 |
| S02 学历不达标 | 学历一票否决 | 初筛不通过（即使 8 年经验、技能全匹配） |
| S03 年限模糊 | 信息不足降级 | 待人工复核（不得直接判不通过；可推估 2018 毕业≈5-6 年） |
| S04 关键字段缺失 | 不编造红线 | 正常流转；手机/邮箱 null + 待补录提示 |
| S05 扫描件 | OCR 兜底链路 | 文本提取为空→OCR→字段可识别 |
| S06 复杂排版双栏 | 版面鲁棒性 | 字段不串位（姓名/电话/邮箱/学历/经历正确归属） |
| S07 语义等价 | （C 域已裁剪）| 本期仅做关键词+模糊匹配，语义召回不做 |
| S08 夸大表述 | （C 域已裁剪）| 本期不做证据审计 |
| S09 加密 PDF | 异常容错 | 友好提示「文件已加密或受保护，请重新上传」 |
| S10 损坏 PDF | 异常容错 | 友好提示解析失败，系统不崩溃 |

## 量化指标（验收协议）

| 指标 | 阈值 |
|---|---|
| 核心字段精确匹配率 | ≥95% |
| 规则拦截与召回率 | ≥90% |
| 关键字段缺失 | 触发待补录/待复核流转，视为功能正常履行 |
| 非 PDF 上传 | 提示「上传简历格式应为 .pdf」，判定为正常合规响应 |

## 执行方式

```bash
# 单测 + 集成（mock LLM）
.venv/Scripts/python.exe -m pytest tests/ -v

# 真实链路（需 .env 配置 DASHSCOPE_API_KEY）
# 起后端后通过 Swagger 或前端上传 evals/golden_datasets/resumes/ 下样本逐一核对
# 业务流：先建需求并挂基准岗位（Java 后端），上传时选定该需求，
# 自动完成 解析 -> 归一化 -> 岗位分配 -> 按岗初筛，在筛选结果页核对
```

## 红线（跑用例时重点观察）

1. 学历/年限/技能被 LLM「自由发挥」判定（淘汰决策必须是确定性规则）
2. 信息缺失被当成条件不满足
3. 解析字段串位/编造
4. 加密损坏文件无友好提示
