# PRD — 智能简历筛选助手（业务基准）

> 来源：《2智能简历筛选助手PRD.docx》，本文件为代码库内的固化版本。AI 与开发者以本文件为业务基准。

## 一、业务背景

HR 收到简历后需按岗位需求筛选简历，并将简历归一化为公司统一格式。传统人工筛选与人工归一化时效性太低。

## 二、目标

1. 批量自动归一化简历。
2. 根据岗位需求批量筛查简历。

## 三、功能清单（Feature List）

| 编号 | 功能 | 模块 | 触发条件 | 前置/后置 | 优先级 |
|---|---|---|---|---|---|
| F-00 | 需求与岗位管理 | 智能识别 | HR 创建需求并在其下建岗位 | 前置：岗位必属一个需求；后置：可挂载简历批次 | P0 |
| F-01 | PDF 简历上传与解析 | 智能识别 | HR 上传简历/文件夹（挂载需求，必选） | 前置：PDF 格式；后置：识别简历内容 | P0 |
| F-02 | 简历归一化 | 智能识别 | 解析完成 | 前置：解析文本；后置：返回归一化简历 | P0 |
| F-02a | 岗位分配 | 智能识别 | 归一化完成自动触发 | 前置：归一化 JSON；后置：简历进入命中岗位组（一份可多岗，HR 可调整） | P0 |
| F-03 | 简历初筛 | 校验 | 岗位分配完成自动触发（亦可按组手动重筛） | 前置：归一化 JSON + 岗位规则；后置：剔除不符合硬性要求的简历 | P0 |
| F-04 | 简历审核与入库 | 校验 | 初筛完成自动触发 | 前置：通过初筛的 JSON + PDF；后置：数据入库（标记通过岗位） | P0 |
| F-05 | 面试邀约与人才沉淀 | 人才库 | HR 在通过人才库操作 | 前置：通过初筛的候选人；后置：面试邀约留痕（interviews）、面试状态流转、沉淀候选人才库（talent_pool） | P1 |

## 四、实体状态机

| 初始状态 | 触发 | 目标状态 | 异常分支 |
|---|---|---|---|
| 等待传入 | 上传 PDF 成功（挂需求） | 文件解析中 | 格式不符（<5M/PDF）→ 提示重新上传 |
| 文件解析中 | 解析成功 | 字段提取中 | 解析失败 → 失败列表，人工审核 |
| 字段提取中 | 提取成功 | 数据归一化 | 失败 → 重试 2 次 → 失败列表 |
| 数据归一化 | 归一化成功 | 岗位分配 | 失败 → 失败列表，提示 HR 人工归一化 |
| 岗位分配 | 全量进入全部开放岗位组 | 按岗初筛中 | 需求下没有开放岗位 → 待人工分岗（不是淘汰） |
| 按岗初筛中 | 各岗规则判定 | 待审核入库 / 待复核 / 不通过 | **任一岗通过即待审核；全部岗位都不满足才出局** |
| 待审核入库 | HR 确认入库 | 结构化入库 | 入库失败 → 提示重新入库 |

## 五、界面交互要点（2026-10 按交互原型定稿：五页导航）

- 导航：工作台 / 需求岗位管理 / 简历上传 / 筛选结果查看 / 人才库管理（简历库、筛选配置保留 URL 直达）
- 工作台：欢迎区 + 快捷入口 + 4 指标卡（进行中需求 / 流水线处理中 / 待人工复核 / 已入库）+ 待办清单（待复核/待补录/待审核/需求截止临期提示）
- 需求岗位管理：4 统计卡 + 需求列表卡（部门/截止日期/负责人）+ 岗位表（岗位编号/招聘人数/专业方向/硬性条件 chips/非技能加分项）+ 岗位弹窗（学历/年限枚举下拉）+ 硬性条件抽屉 + 分组管理 + 重新分配并初筛
- 简历上传：三步指引 + 需求必选 + 开放岗位展示（全量分配）+ 拖拽上传 + 分阶段进度条（解析→归一化→分配与初筛→完成）
- 筛选结果查看：需求→岗位→任务三级联动 + 三态汇总卡 + HR 复核抽屉（左原始 PDF、右归一化字段可编辑，入库/筛除/重试）+ 岗位匹配情况弹窗（各岗判定汇总；匹配度评分建设中）
- 人才库管理：双库——「本次岗位通过人才库」（面试流程状态：待面试→已邀请→面试中→已入职/暂不跟进、发起面试邀约）+「沉淀候选人才库」（长期储备、来源留痕）
- 候选人姓名等字段：归一化后自动填充（只读/可审核编辑）
- 上传区：仅 PDF、单文件 ≤5M、必须选定挂载需求；失败返回原因并提示重新上传

## 六、降级兜底（Fallback）

1. **解析超时降级**：单份响应超时（>10s）或宕机，重试 2 次，仍失败 → 失败列表
2. **归一化失败降级**：超 20s 或校验失败 → 归一化失败，失败列表，提示 HR 人工归一化

## 七、本期范围决策（2026-09 与需求方确认）

- **不做 AI 打分（C 域）**：无 match_score / AI 评价 / 语义召回
- 岗位分配为**全量分配**（需求池简历进入全部开放岗位组，无技能门槛；技能是否满足由初筛三态规则判定），LLM 不参与分配与淘汰决策
- 需求级初筛语义：任一岗位通过即留下，**全部岗位都不满足才筛出去**
- 初筛三态：通过 / 不通过 / **待人工复核**（信息不足 ≠ 不合格）
- 架构图的 filter_templates / filter_runs / filter_results 三表落地（去掉打分字段）

## 八、业务流决策（2026-10 与需求方确认）

- 需求（Requirement）为岗位集合容器，自身不带筛选条件；岗位必属一个需求
- HR 通过邮箱收到简历（邮箱收取在平台外），批量上传挂载需求（必选）
- 上传后全自动串联：解析 → 归一化 → 岗位分配（规则建议）→ 各岗位独立初筛
- 一份简历可分配多个岗位；HR 事后可调整分组并手动重筛（自动/手动来源留痕）
- 全部岗位未命中 ≠ 淘汰 → 待人工分岗
