# 智能简历筛选助手PRD\-最终版

# 一、业务背景

HR 收到简历后，需围绕招聘需求开展简历筛选与格式归一化工作。当前单个招聘需求下通常包含多个招聘岗位及对应岗位 JD，传统人工模式下，HR 需逐份解析简历、统一格式，并手动对照不同岗位 JD 逐一匹配筛选，存在处理效率低、人力成本高等问题，无法满足批量招聘的时效要求。

# 二、目标

1. 实现批量 PDF 简历的自动解析与归一化，输出公司统一标准的简历数据。

2. 将简历自动分配到招聘需求下的全部开放岗位，并按岗位硬性条件分别筛选，支持单份简历同时参与多个岗位的评估。

3. 按岗位维度自动筛选，剔除不符合岗位硬性要求的简历，保留匹配简历待HR审核入库。

4. 提供岗位结果可追溯的简历人工复核能力。HR 确认通过后完成本次筛选；对于需要长期复用的候选人，可另行沉淀至企业人才库，供后续招聘需求检索和复用。

|F\-08|简历审核与人才库沉淀|人工复核模块|HR 对待审核简历进行确认、人工筛除或选择沉淀人才库时触发|前置：展示原 PDF、归一化数据、各岗位筛选结果与汇总原因<br>后置：1\. HR 确认通过 → 本次筛选已完成，并记录通过岗位；2\. HR 人工筛除 → 整份简历进入初筛不通过，原因必填并留痕；3\. 人才库沉淀为独立可选操作，不随审核通过自动发生，可供后续招聘检索复用|P0|

> F-02～F-08 均要求用户已登录；业务操作人统一取当前登录会话，不接受前端自行传入。

|已登录|访问业务页面或调用业务接口|登录会话仍在有效期内且账号状态正常|已登录|允许访问；操作人身份统一取当前登录用户，不接受前端自行传入|
|已登录|用户主动退出|存在有效登录会话|未登录|立即撤销当前会话、清除登录 Cookie，并跳转登录页|
|已登录|登录会话过期或无效|会话达到有效期或校验失败|未登录|拒绝业务访问，返回未认证状态并提示重新登录|
|已登录|账号被管理员禁用|账号状态变为禁用|未登录|撤销该账号的有效会话，拒绝后续访问并返回登录页|

### 2.2 简历处理状态转移表

|**初始状态**|**触发动作**|**目标状态**|**异常分支与降级处理**|
|---|---|---|---|
|等待传入<br>|上传 PDF 成功（关联需求）|文件解析中|非 PDF / 超 5M / 加密损坏→ 拒收并提示重新上传；SHA256 重复 → 幂等复用已有记录|
|文件解析中<br>|解析成功（有效字符过少自动触发 OCR 兜底）|数据归一化中<br>|解析失败 → 解析失败列表，HR 可重试解析重新入列|
|数据归一化中|LLM 归一化 \+ JSON Schema / Pydantic 双校验|简历岗位分配中<br>|校验失败自动重试 2 次 → 归一化失败列表，提示 HR 人工归一化；电话/邮箱缺失 → 待补录（不编造、不判死）|
|简历岗位分配中<br>|简历与需求下全部开放岗位分配完成|按岗初筛中<br>||
|按岗初筛中|各岗硬性规则判定并汇总<br>|待审核入库 / 待补录 / 待人工复核 / 初筛不通过<br>|任一岗通过且电话、邮箱完整 → 待审核入库；任一岗通过但电话或邮箱缺失 → 待补录；无通过但至少一岗待复核 → 待人工复核；全部岗位不通过 → 初筛不通过|
|待补录<br>|HR 补录电话和邮箱并保存|待审核入库|未补全 → 保持待补录|
|待审核入库<br>|HR 确认通过|已完成（记录通过岗位）|HR 人工筛除 → 初筛不通过；原因必填，并以「人工筛除」标记与规则淘汰区分|
|初筛不通过<br>|HR 恢复待筛|待初筛|仅规则或资料修正后重新执行岗位筛选；历史筛选和人工操作记录保留|

> 面试进度使用独立的 `interview_status` 管理，不属于 `resumes.status` 简历处理状态机。候选人才库沉淀也是审核后的独立操作，不改变简历处理状态。

|沉淀候选人才库（talent\_pool）|简历、来源需求/岗位、备注、知识库同步状态/文档编号/切片数/错误摘要/同步时间|长期储备，可移出，供后续需求匹配；仅记录知识库同步结果，不保存 Wiki 正文|

## **2、AI Agent / API 契约**

**LLM 使用边界（红线）**：LLM 仅用于简历归一化字段提取；岗位分配、初筛淘汰决策、面试流转均为确定性规则，LLM 不参与。

- **归一化提取契约**：输入解析后的简历文本，输出必须通过 strict JSON Schema \+ Pydantic 双校验方可落库——

    - 学历枚举：大专 / 本科 / 硕士 / 博士 / 空（未提及）

    - 年月格式：YYYY\-MM；在读/在职经历「至今」以在职标记表达、结束时间为空

    - 简历未提及的信息一律为空，校验失败自动重试，最多 2 次

- **上传接口**：`files`（PDF 批量）\+ `hr_id`（操作人）\+ `requirement_id`（挂载需求，必填）；返回批次号与逐文件受理结果（接收 / 重复复用 / 拒收原因）

- **核心接口（业务视角）**：需求与岗位管理（增删改查、状态切换、重新分配并初筛）、上传与批次进度、按组重筛、筛选结果查询（需求 → 岗位两级）与 CSV 导出、HR 复核（字段编辑 / 入库 / 人工筛除 / 恢复待筛 / 重试解析）、面试流程（状态标记 / 邀约）、沉淀人才库（入库 / 移出）

- **结果输出规范**：初筛结果三态（通过 / 不通过 / 待人工复核）\+ 逐条判定明细（规则项、是否满足、判定说明），示例：

```JSON
{
```

## **3、降级兜底容错方案（Fallback）**

1. **解析超时降级**：单份响应超时（\>10s）或宕机，重试 2 次，仍失败 → 失败列表，HR 可重试解析

2. **归一化失败降级**：超 20s 或校验失败 → 归一化失败列表，提示 HR 人工归一化

3. **扫描件 OCR 兜底**：解析文本有效字符过少 → 自动转 OCR 识别，字段仍按双校验落库

4. **加密/损坏 PDF**：上传或解析阶段友好拒绝（"文件已加密或损坏，请重新上传"），系统不崩溃

5. **批次进度**：处理状态实时可查，页面切换不丢失；异常批次自动停止轮询不阻塞
